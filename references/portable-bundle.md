# 可移动预演包

来源在工程目录外时，不要只压缩预演子目录。使用：

```text
node scripts/bundle.mjs --project <已绑定的预演项目> --out <项目外不存在的新交付目录>
```

工具复用项目的来源范围校验和渲染输入指纹，保留项目与显式外部来源的相对路径，在稀疏 `tree/` 中按原字节复制；`scene`、intake、既有视频和回执都不改写。目录顶层 `bundle-manifest.json` 指出 `project_root`、启动命令及入口，按该位置运行 `node scripts/serve.mjs`。

排除 node_modules、.hyperframes、.git、临时/日志/锁。保留本地 Three.js 依赖，预览不需要重新安装；重新导出运行 `npm ci` 安装锁定依赖。项目带有仍在运行的保存/导出锁时，先等待完成；异常退出留下的锁需先核实无进程，不自动抢占。

只复制 intake.sources、资产绑定和渲染指纹已明确列出的依赖；未交接的资产提示词不能在包内声称可复核。绝对路径、跨盘引用和 URI 不能原样构成可移动相对关系，工具会明确拒绝，先在新修订中把真实依赖本地化再重新绑定/导出；不静默重写原证据或旧回执。

包内上游材料标为 `READ_ONLY_EVIDENCE_SNAPSHOT`，首次证据哈希与实际复制哈希分别保存。它支持复核或修改该历史版本的预演；不能据此证明原项目此刻仍然有效，不能替换权威状态、推进覆盖或用作自动恢复制作。离线的“视频对应当前输入”仅指包内冻结输入。打包没有发生新渲染。

复制失败不会写完成 manifest；部分文件保留作诊断，不作为完成交付。整个新包完成后再压缩交付，不把孤立的 `tree/` 子项目再次单独压缩而丢失其兄弟依赖。
