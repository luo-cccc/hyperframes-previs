实现由3个agent承担限定代码范围，随后使用3个独立agent分别审查代码、模拟上游接收与迁移、模拟运行时使用。初始失败、实现修复、定向复测和冻结结果分开保存。

| 发现 | 修复与最终复测 |
|---|---|
| P1：刷新接口继续显示失效验收为已完成 | GET复用只读createHandoff求值，重新核对证据、计划、所有端点及包；过期时返回current:false及实际目标状态，不改写已发布文件。独立复现关闭。 |
| P2：未知显式转场ID可被当成来源通过 | 实际提取要求明确ID在两端证明CURRENT，否则拒绝；plan-only仅记录未验证计划。独立复现关闭。 |
| P2：锁/历史/目标元数据让相同接点过期 | 接点身份和源场景快照采用规范化渲染内容，原始文件取证仍在原渲染回执。实际保存锁后身份、冻结文件和相关检查仍有效。独立复现关闭。 |
| P2：真实four_views版本无法按文档绑定 | 明确typed字段或LOOK-/STATE-组合token被解析为同一实际四视图记录；拒绝跨记录拼版本或从自由文本推断。真实归档首轮绑定与错误LOOK/STATE三项复测通过。 |
