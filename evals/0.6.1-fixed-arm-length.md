# 0.6.1 固定手臂骨长修复

日期：2026-11-06（Asia/Shanghai）。基线提交 af4064138934aca58bf3f9142e38343ccba7cb30。

用户从实际预演视频发现手臂忽长忽短。本次修复覆盖固定上臂／前臂、真实手腕位置和可达性诊断。旧视频与原始失败记录保留，新视频另存。

## 原因和处理

原 renderer 把肘部放在肩与目标中点附近，再通过 mesh.scale.y 把两段手臂拉到目标。旧 gap=0 只能说明手被放到了目标点，不能说明固定骨长能达到该位置。

新增 limb-ik.js 的绝对时间双段求解；基准 1.8 米代理的上臂 0.32 米、前臂 0.28 米，随角色的固定身高／竖向尺度同比例确定。每帧求肩、肘、腕角度，手臂几何本身定长，渲染矩阵抵消父级非均匀缩放，世界骨长不会随角度变化。

hands.position 为实际手腕，hands.target_position 保留原请求目标；hands.ik 记录固定长度、可达性与真实 reach_error_m。超远与过近目标夹到可达范围，接触 gap 使用实际手腕计算。相机、原段、时长、上游原文和角色路径没有为消除间隙被改写。

普通 handKeys／门接触与战斗接触都进入该检查；Studio 可定位哪只手超出臂展及其米制间隙。手部伤损作为 attachment_role=surface 的 mark 随实际手腕移动，不占用持物名额，其他物件仍受一手一物约束。

独立测试覆盖可达、超远、超近、完全伸展、零距离、共线 pole 退化、左右手、刚体变换、uniform/nonuniform scale、非法输入和非顺序调用。真实浏览器比较的是网格顶点边界的世界端点；没有用 scene 中的声明长度冒充实际网格。

首轮原契约中把目标点直接当手腕的断言被纠正为“原目标不变＋定长实际手腕＋真实残差”。跨段关键点精确取原 knot，避免由浮点插值给附着标记引入边界数值差异。原有接收、来源、预算、状态图和视频接点测试继续执行。

## 独立审查闭环

原 R1：无 combat 的合法 handKeys 有 4.115 米不可达残差，通用空间检查没有报警。已将相同可达性检查接入普通场景；同一原 fixture 独立复测返回 ARM_TARGET_UNREACHABLE。

原 R2：省略 light.color 的光源执行未来色彩事件后，回跳及 captureStateAt 恢复没有重置基础灯色。现在每帧从当前事件／声明／物体基础色确定灯色；新 Chrome 独立复测回跳前后及未来截图恢复前后的 PNG 均逐字节一致。该项同本轮非顺序与状态恢复检查一起修复。

两项原始 FAIL 和旧源码快照均保留；最终独立记录为 R1 CLOSED、R2 CLOSED，浏览器及自有服务已关闭。另有首轮全量验收因测试临时目录未创建而出现 23 项 ENOENT，归为 harness 失败并保留；补建隔离目录后实际重跑通过，没有把它改写成产品故障或删除历史。

## 当前画面范围

固定骨长修复没有把已有不成立的姿态强行变成成立。原第四类 14.2 秒仍采用站立代理去够地面炉壳，实际腕位保留约 0.510 米间隙并报告不可达。烧痕跟随实际腕位。后续若要该接触成立，需要按原文做蹲身／俯身的全身姿态排演，而不能再次拉长手臂。

全帧原始统计共有 11,287 个不可达手部采样（时间／角色／左右手组合），最大残差约 1.664 米；这些是新检查显露的旧动作轨道限制，不是 11,287 个独立问题，也没有被算作语义 PASS。修复覆盖上臂和前臂；完整关节限位、肩胛、腿部支撑、布料受力与最终角色动画保持其实际实现范围。

新版四类、12 段视频仍为 1280×720、60fps，共 137 秒／8,220 帧，并重做 51 张原状态 PNG 与 33 组真实视频接点。每段 render receipt、source fingerprint 与相应保存工程匹配；旧证据没有搬成新版通过记录。新增可达性与真实接触检查后，fight-check 共保留 131 组告警，12 段的 FIGHT_PREVIS 均为 BLOCKED；没有用 527 项软件回归通过替代动作语义验收。
